│                                                                                                      │
│                        BBN-Driven Proactive Fault Tolerance for Fog Computing                        │
│                                                                                                      │
│   A causal Bayesian Belief Network learns, from the telemetry of iFogSim fog devices, the            │
│   probability that each node will fail within the next two epochs -- and a controller inside         │
│   the simulator uses that probability to migrate and replicate services before the failure.          │

2  The simulated system ────────────────────────────────────────────────────────────────────────────────
Every node below is an iFogSim FogDevice subclass (InstrumentedFogDevice) running inside CloudSim's 
event loop.
Cloud  (1 datacentre, archival + fallback analysis)
├── Fog tier  118 gateways from the Melbourne CBD edge-resource dataset; each hosts an ecg_analyser
│   ├── telemetry agent: CPU, RAM, queue, uplink latency, jitter, handovers, residual energy, 
│   │   temperature + 5 trends
│   └── hidden health that wears under sustained load and heat; fails slow, then stops
└── Edge tier  20-80 patients' devices moving along the Melbourne CBD mobility traces
    ├── client module filters vitals; alarm actuator; battery drains
    └── criticality: 25% critical (ICU), 45% standard, 30% best-effort

  Failures come from a stress-driven degradation model with fail-slow symptoms; 1 in 5 failures is

5  Training the BBN on the devices' telemetry ──────────────────────────────────────────────────────────
Structure: the paper's Fig. 2 plus validated trend evidence and device-class conditioning; CPTs learned 
by MAP-EM (latent stress is never observed).
node_failure  P(fail within 2 epochs | evidence)   <- 4 latent conditions + reliability prior
├── computational_stress  <- cpu_util, ram_util, queue_depth, cpu_trend, queue_trend (+ device class)
├── network_degradation  <- uplink_latency, jitter_pktloss, handover_rate, latency_trend (+ device 
│   class)
├── energy_stress  <- residual_energy, energy_drain (+ device class)
├── thermal_stress  <- temperature, temp_trend (+ device class)
└── reliability_prior  (device class: cloud / fog / edge)
  chosen by internal validation on training scenarios only: learned ranked-node latent tables, 
supervised evidence bins (up to 8 per channel, per device class), Dirichlet concentration 1, 60 EM 
iterations (CV PR-AUC 0.759; paper graph with tertiles 0.041)
  EM ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 60/60 iterations log-likelihood -0.00961
  ✓ 314,323 snapshots -> 43,374 distinct discretised patterns; trained in 10.6 s
  ✓ retrained from scratch = data/bbn_trained.json, the model behind every reported result and read by 
the Java controller (largest CPT difference 0.0e+00)

7  LIVE: the trained BBN running proactive fault tolerance inside iFogSim ──────────────────────────────
Every epoch the controller reads each fog node's telemetry, computes P(fail) with the BBN, migrates 
sessions when P(fail)·C_fail > C_mig, sets redundancy by P(fail)·κ, and learns online.

9  Verdict: why the BBN ────────────────────────────────────────────────────────────────────────────────
╭───────────────────────────────── evidence from this project's runs ──────────────────────────────────╮
│                                                                                                      │
│   ● As accurate as the best black box.  PR-AUC 0.639 vs Random forest 0.651 (95% intervals overlap); │
│ ROC-AUC 0.866 (best of all models).                                                                  │
│   ● Calibrated probabilities.  Brier 0.00128 (best), ECE 0.0005 (best) -- the controller multiplies  │
│ P(fail) by a cost, so this matters.                                                                  │
│   ● Close to what is achievable.  122 of the 422 held-out failures are sudden (no precursor). A      │
│ predictor clairvoyant about all the others would score ROC-AUC 0.872 and PR-AUC 0.712; the BBN       │
│ reaches 99% and 90%.                                                                                 │
│   ● Missing telemetry.  With 30-60% of channels missing, more often on degrading nodes, the BBN      │
│ keeps the best probabilities (log-loss 0.0171; best alternative 0.0189, Gradient boosting); for      │
│ ranking, Naive Bayes holds up best (ROC-AUC 0.821, BBN 0.700). Missing channels are summed out,      │
│ never imputed.                                                                                       │
│   ● Works before any failure is seen.  With only the expert-elicited tables, ROC-AUC 0.750 and       │
│ PR-AUC 0.015 (5.5x the chance level 0.0026); a classifier cannot be trained at all without failure   │
│ labels.                                                                                              │
│   ● Explains every alarm.  Each P(fail) comes with the latent condition driving it (computational,   │
│ network, energy or thermal stress) -- shown live in stage 7.                                         │
│   ● vs no fault tolerance:  downtime from failures + migrations -97% (p < 0.001), critical patients' │
│ downtime -82% (p < 0.001).                                                                           │
│   ● vs reactive checkpointing (Rajab 2021):  downtime from failures + migrations -85% (p < 0.001),   │
│ critical patients' downtime -58% (p < 0.001).                                                        │
│   ● vs FTAPA threshold migration (Gupta 2025):  downtime from failures + migrations -55% (p =        │
│ 0.002), critical patients' downtime -39% (p < 0.001); warm standby for 0.2% of sessions against      │
│ 100%.                                                                                                │
│   ● vs the same controller driven by ML:  complete telemetry +18% (p = 0.122), not significant; with │
│ 30% of telemetry missing, more often on degrading nodes, -29% (p = 0.006).                           │
│   ● Against a perfect predictor:  of the failure downtime a perfect predictor removes (no fault      │
│ tolerance 517 ms per user, oracle 15 ms), the BBN framework removes 99% (20 ms).                     │
│   ● Cloud-only is not an option for critical patients:  least downtime, but loop p95 310 ms misses   │
│ the 150 ms deadline on every critical alarm.                                                         │
